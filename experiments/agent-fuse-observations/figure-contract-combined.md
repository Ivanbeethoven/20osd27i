# Compact workload figure and evidence contract

`fuse-combined-compact`, generated by `plot_combined.py`, replaces the previous
four-panel profile and separate two-panel time figure in the manuscript. Old
exports, `plot.py`, and their contract are preserved as companion diagnostics.

**Question:** Which measured request properties should the evaluation preserve?

**Conclusion:** These eight captures combine substantial metadata traffic,
mixed request sizes, and task-specific bursts. They motivate evaluation coverage,
not a BrewFS performance claim or a general claim about coding agents.

| Panel | Evidence role | Exact transformation |
|---|---|---|
| a — Request mix | Establish the operation classes and negative-request contribution | Partition every group event into the six-method metadata subset, read, write, or Other. Errors are part of each class's total. |
| b — Sizes (KiB) | Decompose I/O into small, intermediate, and large requests | Sum exact integer-byte histograms in `(0,4096]`, `(4096,65536]`, and `(65536,infinity)`, separately for read/write and both groups. |
| c — Bursty tasks | Bound a group-average description with every task's temporal concentration | Select the largest `ceil(0.1 * window_count)` of all 1-s windows, including zeros and the final partial window; divide their count by all calls for that task. |

The quantitative grid uses three equal plot areas. The previous top-12 method
detail, exact ECDFs, and cumulative curves remain available but no longer occupy
separate main-text panels. Readers can now see burst concentration directly,
rather than infer it from curves with different absolute time/count axes.

## Data and statistics

All 1,138,884 events are included, stratified into Core (217,129 events; five
tasks) and Exploratory (921,755 events; three tasks). Group bars weight events
equally; eight task markers are never pooled. Each task was observed once. No
confidence interval is calculated from correlated requests and no replicated
performance result is implied. Group differences confound repositories, prompts,
and budgets.

Sources are the unchanged derived `summary.json`, `request-sizes.csv`,
`tasks.csv`, and `timeseries-1s.csv`. `qa/combined/plotted-data.json` records
every aggregate drawn. Assertions check complete partition totals, every
group/method size denominator, all eight identities, time-series totals, and
recomputed burst fractions against the validated task table. No observations
are excluded or downsampled.

The metadata subset remains lookup/getattr/getxattr/readdirplus/opendir/releasedir.
Other retains file open/flush/release and all remaining non-read/write methods.
White in (a) encodes errors; color retains ok and incomplete records. White in
(b) encodes >64 KiB, as stated in its separate key and caption. All recorded
read/write events are ok.

Requested FUSE lengths are not object lengths, unique bytes, syscall sizes, or
optimal storage block sizes. These captures do not establish sharing, sparse
mutation, an automatic-policy advantage, or latency gains. Task-level metadata
shares and read/write-ratio ranges remain in the prose.

## Export and QA

Python/Matplotlib is the established backend. Export is exactly 7 x 2.75 inches
(504 x 198 pt), matching the manuscript text width. Every plot area is 102 x
112 pt; horizontal gutters are 65 pt. Visible glyphs are 9.5–10.5 pt rather than
the previous 8 pt. Combining 4.45 inches of image height into 2.75 reduces it by
about 38% while increasing text size. PDF and editable SVG are primary; PNG is
a 300-dpi preview.

Full-data assertions, a 1.5-pt render-time alignment gate, actual PDF font audit,
source preflight, and final PDF collision audit are required. See
`qa/combined/review.md`. The 100-dpi placement proof is a screen QA artifact,
not a submission raster.
