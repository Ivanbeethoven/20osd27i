# BrewFS 框架图：先让共享关系和局部修改被看见

这是依据四篇 OSDI ’26 方法图重构的第一版设计草图，供作者审阅。
图的尺寸仍为 504 × 230 pt（7 × 3.19 英寸），与原 compact 图相同；
全部文字为可编辑 Arial，8–9 pt。图文件尚未替换论文中的活动图。

## 本版的视觉重点

1. **先看见共享什么。** 两份工作区下方只出现一份不可变快照 S，主画面占约三分之二宽度。
2. **再看见如何独立修改。** 同一逻辑文件的 A/B/C 区间，视图 i 改 B，视图 j 改 C；Data 箭头指向各自私有对象。
3. **最后追踪技术表示。** Packed 用索引、联合记录和 frame 条带展示表示；B/q 用有效的 2+2 微例展示持久化几何。
4. **颜色始终有含义。** 蓝色表示共享 lower，浅橙表示新增私有数据。区间标签同时编码语义，灰度下仍可区分。

这张图表达的是机制，不是跨任务读集重叠、稀疏修改频率、空间节省或性能提升的实测结论。
两份区间条是示意，等宽区间不表达工作负载比例。Hole 在图注中说明，主图聚焦改写实例。

## 核对

- 上层读取仍为整对象校验后切片；图内保留这一限制。
- Lower 标签表示显式 LowerRange；不能把映射缺口理解成自动继承。
- 图中 pin S 是身份绑定，不是读请求的必经顺序。
- Packed 仅展示代表性名字查询；其他索引和直接 frame 路径由图注限定。
- hint 的输入是最终对象长度，虚线明确表示待集成。
- smaller q 默认关闭；示例按两个 gate 开启、适用新对象绘制。
- B=256 KiB，d=p=2，每 shard 为 128 KiB，q=64 KiB；Packed frame 与 q 不等价。
- 读与修复解释对象已持久化的布局，不根据当前 hint 重新选择。
