## Reading the diagram

1. FUSE operations can use either an ordinary volume or delta-based workspaces. Workspaces resolve private state first and pin a shared immutable baseline. Both view types connect to parallel metadata and data interfaces; neither lower branch requires the workspace mechanism.
2. Native and Packed remain alternative metadata representations. Their upper icons compare three separate record cards with the same three records sharing one page. Each record has the same three field marks, corresponding to Name, Attributes, and Data ref. in the expanded page. This expresses packing multiple complete metadata records, not packing only one file's attributes or its payload. The expanded joint page contains one named record (`main.py`) and two complete schematic record rows. A separate read-only mount enters the name-range index, while the data-reference column connects straight down to existing file bytes. Descriptor resolution remains abstracted here and is expanded in Figure 3.
3. **Ordinary upload · fixed g** shows different files forming objects under the same configured volume geometry, after applicable formatting. The object paths join before entering **Backend · layout choices**: no file is assigned a particular B. Two equal schematic object extents compare small and large coding-block choices, separated by `or`; each retains a short tail. One selected complete B block expands into shards. An ellipsis avoids specifying data/parity counts, while **Read/verify q** brackets the highlighted initial half of one schematic shard. Both B choices are backend design/interface alternatives for eligible objects, not a claim that the current automatic policy selects B by file type or length. Current automatic hints may retain the default B. Independent admission gates, per-producer contracts, and persistent object geometry remain as specified in Sections 6–7. No per-file g selection, online sizing controller, or proportional g/B/q coupling is claimed. The main figure uses no numeric backend scale.

Orange denotes private workspace state; blue denotes shared immutable records/data; gray denotes ordinary object formation and backend layout. Choice boxes and the common-interface branch encode optionality without relying on color. Repeated U₁/Oₚ ports from the preceding version have been removed.
