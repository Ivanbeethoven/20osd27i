\begin{abstract}
Coding agents can share a repository baseline while keeping edits private,
but sharing does not determine metadata and data access costs.
\sysname{} separates shared-version identity from metadata and object
access units through three independently optional mechanisms.
Delta-Based Workspaces resolve a shared baseline with private changes;
Packed Metadata places names, attributes, and data locators in indexed
object-resident pages; Variable-Granularity Object Storage separates
client object formation from optional backend encoding and verification.
Our hypothesis is that these choices reduce lifecycle storage work when
reuse or selective access repays construction and maintenance, under
matched visibility and durability contracts. We explain inode identity,
atomic namespace updates, truncation, publication, and persisted layouts,
then identify the implementation boundaries relevant to their evaluation.
A reanalysis of 1,138,884 FUSE requests from eight coding-agent task runs
characterizes metadata traffic, read/write sizes, and temporal heterogeneity.
The planned evaluation isolates overlay, metadata offload, and object
granularity, then tests fork, migration, and concurrent workloads with
JuiceFS as the external comparator. It accounts for construction,
retention, caching, and failure outcomes. The workload
observations do not establish system speedups.
\end{abstract}
