\section{Related Work}
\label{sec:related}

\paragraph{Private workspaces.}
OverlayFS combines upper and lower trees through copy-up and deletion
markers~\cite{overlayfs}. BranchFS adds a fork, explore, and commit
lifecycle; its evaluated prototype copies an inherited file on first
modification~\cite{branchfs2026}. \sys represents private names,
attributes, and file ranges over an immutable baseline. Unchanged ranges
retain their original references, and the lower-query interface accepts
native or packed metadata. The distinction is the state copied and
resolved on each operation. YoloFS provides staging, reversible effects,
and permissions~\cite{yolofs2026}; AgentFS records files, key-value state,
and tool calls in SQLite~\cite{agentfs2025}. These systems address
execution control and observability, which can use the workspace and
storage mechanisms described here.

\paragraph{Mutable metadata services.}
TableFS and IndexFS organize metadata and small files in tables;
IndexFS also partitions directories and supports caching and bulk
insertion~\cite{tablefs2013,indexfs2014}. LocoFS and InfiniFS distribute
metadata responsibilities~\cite{locofs2017,infinifs2022}, while Mantle
and SwitchFS address hierarchical metadata and asynchronous directory
updates~\cite{mantle2025,switchfs2026}. These designs improve mutable
metadata service. \sys instead specializes the service path of a selected
read-only version: supported lower queries fetch object-backed pages.
Private updates and lifetime control remain in the mutable service.
The resulting tradeoff is database query work displaced versus page
access and version-publication cost.

\paragraph{Backups and mountable snapshots.}
JuiceFS exports metadata that an operator can load into a metadata
engine for recovery or migration~\cite{juicefs_backup}. Some backups
also support direct reads: restic represents directories as trees,
indexes blobs by content ID, and exposes snapshots through a FUSE
mount~\cite{restic_backup}. In \sys the access unit for a name is a
bounded range within one directory. The index identifies the bytes
containing that range's names, attributes, and data locators. A
workspace can use this representation as its live read-only lower while
sending private updates to its upper.

\paragraph{Private namespaces and immutable logs.}
DeltaFS publishes private-namespace mutation logs as SSTables for
subsequent jobs to select and merge. Job-local servers and compaction
reduce dependence on a globally synchronized metadata
service~\cite{deltafs2021}. \sys maintains a current-value private upper
over a pinned lower. A separate publication step can organize the lower
by directory and name range, placing attributes and data locators beside
names. Native-metadata workspaces omit that construction. The two designs
therefore differ in how private updates are represented and when an
immutable query representation is built.

\paragraph{Read-only distribution and indexing.}
CernVM-FS uses nested SQLite catalogs to publish content-addressed trees
and fetch metadata and data on demand~\cite{cvmfs2011}. It directly
demonstrates the value of serving immutable collections outside a mutable
metadata service. OCI specifies layered archives~\cite{oci_layers};
SOCI indexes image data for lazy access~\cite{soci}. Nydus separates
filesystem metadata from chunked data and supports caching and integrity
verification~\cite{nydus_rafs}. Slacker and DADI likewise use
demand-driven access for image distribution~\cite{slacker2016,dadi2020}.
These systems provide close precedents for immutable, remotely accessed
file representations.

CoFS specializes a fixed image namespace with minimal perfect hashing
and a dense metadata array. In-kernel lookup avoids userspace
interposition on cached-data paths~\cite{cofs2026}. \sys organizes
directory names, attributes, and data locators into bounded joint pages
reached through authenticated range indexes. A page is the remote
metadata access unit, independently of its physical container. This
organization targets repeated queries over a published directory version
alongside mutable agent workspaces. Compared with image indexes and
catalogs, the relevant differences are the records fetched per operation,
their reuse across queries, and the cost of constructing and retaining
each version. The comparison concerns access during execution as well
as initial materialization.

\paragraph{Object granularity.}
Ceph and Tectonic separate metadata and storage
services~\cite{ceph2006,tectonic2021}. Azure's erasure coding reduces repair
traffic; Morph studies redundancy transitions over a file's lifetime;
Okapi separates striping from redundancy
grouping~\cite{azureec2012,morph2024,okapi2025}. Our co-design with RustFS
connects filesystem object formation to per-object coding geometry.
The client can request a coding-block size after forming an object.
RustFS validates the hint, selects verification framing under a separate
policy, and persists the effective layout for reads and repair. The
interface exposes these access units while retaining the backend's
erasure code and its control over admissible layouts.
