\section{Related Work and Scope}
\label{sec:related}

\paragraph{Workspaces and agent-native file systems.}
OverlayFS provides layered namespaces with a private upper and shared
lower~\cite{overlayfs}. BranchFS applies copy-on-write branch contexts to
agentic exploration, with a commit/abort lifecycle described through a
workshop prototype and a proposed kernel abstraction~\cite{branchfs2026}.
YoloFS addresses visibility and control over agent effects through staging,
snapshots, and permissions~\cite{yolofs2026}; AgentFS documents a file-system
and tool-state abstraction for agents~\cite{agentfs2025}. These systems
establish the workspace mechanisms on which this work builds. \sys focuses
on remote metadata and object access; process isolation and approval of
agent actions require separate runtime policies.

The comparison must distinguish a local private view from a remotely
durable one. OverlayFS and BranchFS are useful controls for workspace
creation and mutation; their persistence boundaries must be matched or
reported separately. JuiceFS supplies an object-backed volume baseline
with a metadata service and chunk/slice/block data
organization~\cite{juicefs_architecture}. These comparisons test the costs
of inherited versus materialized metadata, private updates, and object
access, rather than treating the presence of a private upper as a new
mechanism.

\paragraph{Namespace and metadata organization.}
TableFS, IndexFS, LocoFS, and InfiniFS organize, partition, and cache
metadata to change the work required by file-system
operations~\cite{tablefs2013,indexfs2014,locofs2017,infinifs2022}.
Recent systems also study hierarchical object metadata and distributed
update coordination~\cite{mantle2025,switchfs2026}. Their access paths make
record layout, batching, and cache reuse relevant comparison criteria:
a metadata service need not issue one remote request per file operation.

DeltaFS is a particularly close conceptual predecessor. It uses private
namespaces and immutable mutation logs over shared storage, with selective
composition of prior state~\cite{deltafs2021}. \sys builds on the separation
of shared state and private changes. Its current-value upper and Packed
Metadata's directory-oriented groups are concrete representation choices
to compare with immutable logs and sorted records. An internal sorted-KV
control can isolate co-location and indexing costs; it cannot establish
superiority over the DeltaFS system or replace a compatible system-level
comparison.

\paragraph{Immutable distribution and storage backends.}
CernVM-FS provides demand-driven software distribution with indexed
catalogs, while Nydus describes metadata/data organization for lazy
image access~\cite{cvmfs2011,nydus_rafs}. Slacker and DADI also address
image distribution and startup costs~\cite{slacker2016,dadi2020}.
Our strongest simple composition baseline combines a mature immutable lower
with a compatible writable upper and object backend. It already
shares state and fetches it on demand. The evaluation must determine
whether \sys changes useful records per fetch, excess payload transfer,
or construction and staging costs at equal content, cache capacity, and
persistence. Standalone lower access and complete writable workspaces
require separate comparisons; neither the proposed interfaces nor their
composition establishes an advantage by itself.

Distributed systems such as Ceph and Tectonic separate aspects of metadata
and data services~\cite{ceph2006,tectonic2021}. Erasure-coded storage research
considers repair cost, changing redundancy over a file's lifetime, and the
relation between data placement and
redundancy~\cite{azureec2012,morph2024,okapi2025}. Okapi's separation of
striping and redundancy grouping is different from our $(B,q)$ distinction,
although both motivate making coupled decisions explicit. Client block
granularity $g$ additionally determines how file data forms objects; it is
distinct from backend coding and physical verification granularity. Our
comparisons hold the code rate fixed and separate object counts, checksums,
tails, and repair work. A smaller unit can reduce over-read without reducing
the nominal redundancy ratio, and can increase checksum or repair cost.

\paragraph{Scope and unresolved evidence.}
Poor name locality, high mutation, rapid version churn, and large
sequential reads can erase the expected savings. The current entry points
and lifecycle support further bound the comparisons
(Section~\ref{sec:implementation}). The planned evaluation must establish
where each mechanism repays its cost and whether a supported combination
improves on its best individual configuration and the direct composition
baseline.
