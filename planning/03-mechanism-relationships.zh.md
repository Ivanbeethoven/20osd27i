## 核心关系

BrewFS 的基础是文件接口、元数据服务和对象数据路径。三项能力分别改变**工作区视图的构成**、**不可变元数据的表示和获取方式**、**数据对象的形成及后端物理布局**。它们作用于不同层，具有各自的启用时机和代价。

| 能力 | 回答的问题 | 启用后的作用 | 不启用时 | 与其他能力的关系 |
|---|---|---|---|---|
| 增量工作区 | 多个任务如何共享初始状态并独立修改？ | 固定共享基线 S，各工作区持有私有增量状态 Δ_i，按覆盖规则解析视图 | 普通卷直接访问自身的元数据与数据映射 | 基线可由原生目录层／KV 表示；Packed 是基线表示的一种选择 |
| 打包式元数据 | 已固定的元数据如何存放、索引、读取和复用？ | 将不可变记录组织为有界页面与索引，从对象获取并验证所需记录 | 使用原生目录层／KV 等元数据表示 | 可独立只读挂载；作为工作区下层时复用同一快照，但不负责私有修改语义 |
| 可变粒度对象存储 | 文件数据形成多大对象，读写与校验需要处理多少字节？ | 选择客户端对象块大小，并可请求兼容后端的编码布局 | 采用固定客户端块大小和后端默认布局 | 普通卷、工作区新增数据和快照对象均有对象访问需求；不以启用前两项为前提 |

可选性是架构职责与配置的分离，不等于当前任意入口都实现了所有组合。当前普通 `flat-v1`、`workspace-v1`、实验性 Entity、Native P1、独立 Packed 挂载具有不同的接线与契约；组合的可运行性必须由所选入口证明。

可以用三个独立场景理解：一个普通可写卷只需原生元数据和默认对象路径；多个任务需要独立修改时，可以在固定的原生目录层上增加私有增量；一个只读发布环境可以直接挂载 Packed，而完全不创建可写工作区。若多个任务反复读取同一稳定环境，再把 Packed 用作这些工作区的共享下层。是否调整客户端对象块大小、是否请求后端布局，继续由各自数据路径决定。

因此，组合时的联系是“复用彼此的输入和接口”：增量工作区调用下层查询接口，Packed 可以实现这个接口；Packed 与私有上层都可能引用数据对象，对象层负责这些对象的传输与物理存储。不能从这条调用关系推导每一项都必须启用，也不能直接推导性能收益会叠加。

## 当前代码实际支持的选择

| 入口 | 已核验的能力 | 需要保留的限制 |
|---|---|---|
| `flat-v1` | 普通元数据与对象路径；可配置客户端块大小 | 固定卷几何，不是在线按访问自动选档 |
| `workspace-v1` | 原生目录层作为基线；有 Packed binding 时才连接 Packed 下层 | 需要所选 catalog 的权限、ID 与生命周期能力；Native 这里不等于 `native_base` |
| `packed-metadata-v3` | 独立只读挂载，无私有可写上层 | 当前使用 wire005；旧 v1/v2 CLI 不支持；独立入口要求零 payload cache／prefetch |
| `workspace-native-v2` | Native P1 KV 工作区与数据路径 | 当前 CLI 拒绝 frozen-metadata feature，不能把库组件存在写成入口已接通 |
| `workspace-entity-v1` | 实验性 Entity 上层与 Packed 下层 | 当前 Redis/S3 fresh-only；其限制不代表全部工作区机制的必要条件 |
| 兼容 RustFS 研究后端 | 可选 B hint 与另行启用的 q 写入布局，按对象持久化 | 客户端编译特性与服务端兼容性开关均有门槛；Entity／fixture 部分路径尚未传递 hint |

当前已存在有条件的 same-PVC Packed v3 恢复入口，不能笼统说所有恢复都没实现；它也不等于任意跨 Worker 的 Entity 接管。Native 的封存、发布和引用式 fork 有库协议及测试调用，本轮没有发现普通 CLI 对这些生命周期函数的完整接线。论文按这些具体范围陈述，不将 PPT 中的接力方案写成已经完成的端到端验证。

## 必须补回的两组区别

1. **dirty overlay 与工作区增量状态。** dirty overlay 在本客户端读取路径中覆盖尚未完成写回的字节；工作区增量状态决定跨工作区的名称、属性和数据映射可见性。前者的本地可读性不等于远端持久化，也不等于已发布恢复版本。
2. **客户端 Block 与后端 B/q。** 以 g 表示 BrewFS `ChunkLayout.block_size` 所定义的客户端对象块粒度；L_o 保持最终上传对象长度；B 保持纠删码编码块大小；q 保持物理校验／读取粒度。压缩、头部和尾块会使 L_o 与 g 不同。PPT 的 1/4/8/16 MiB 是客户端对象粒度的研究示例，不是后端 B 的候选值，更不是已实现自动选档的证据。

- 增量工作区：定义覆盖、删除、数据映射、发布与持有关系；以原生下层和 Packed 下层解释可替换性，单列 dirty overlay。
