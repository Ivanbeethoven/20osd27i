# BrewFS 研究规划审阅意见

审阅日期：2026-10-22。

使用技能：`skills/osdi-systems-paper/SKILL.md`。

审阅对象：`planning/01-research-outline.zh.md` 与 `planning/02-experiment-plan.zh.md`。未修改被审阅文件。以下位置对应审阅时的文件版本；后续修订可能改变行号。

## 总体判断

两份文档已经形成可继续推进研究的完整证据链，并明确区分规范、源码、接线和测量。它们承认当前集成缺口、默认关闭的 q、可能不改变 B 的 auto 规则，以及 Entity upper 整对象读取带来的约束。这些边界与初稿的诚实性相符。没有发现编造性能数据或将计划结果写成已经完成的实验。

现阶段最需要修改的不是增加更多实验，而是将代价模型、主要分析终点和执行优先级进一步具体化。下面六项值得在正式运行之前解决，其中 A1–A3 应直接反映在本次规划文本中。

## A1. 将构建摊销模型与并发墙钟时间分开

**位置：** 实验计划 E07，第 214 行；§8.3，第 323 行。

当前 `C_total(K)=C_build+C_publish+Σ(C_provision_i+C_access_i)+C_reclaim` 对同一种可加资源成立，例如 CPU seconds、传输字节、请求费用或按固定费率折算的支出。但是各工作区并发执行时，累计 per-task wall-clock 不能解释成整批任务 makespan；CPU、内存峰值和请求数量也不能在未定义权重时合成一个“总成本”。

**建议修改：** 将 `C_total` 定义为带单位的资源向量或分别报告 `C_cpu`、`C_network`、`C_requests`、`C_storage`。如果使用货币标量，明确执行日期和各资源单价。将 batch makespan 单独定义为最早请求至最后合格完成的时间，由关键路径测量。break-even 应明确是哪项资源或哪种固定服务目标的盈亏平衡，并在各并发点分别估计。

**原因：** 当前文本其他地方已正确讨论重叠，E07 若不限定 C 的含义，会引入与该原则相冲突的解释。

## A2. 明确失败、超时和重复任务的主要统计终点

**位置：** E13，第 264–270 行；统计计划第 330–332 行。

每任务每条件三次运行会产生任务内相关性。普通 McNemar 检验以独立匹配二元样本为前提，不能直接把三次运行当作三倍独立任务。当前 “completed-only 和 intention-to-treat” 是正确方向，但尚未规定后者具体如何计算，因此快速失败仍可能被错误纳入低平均耗时。

**建议修改：** 对成功率优先采用 task/repository 层次清楚的配对聚类分析，或先预先定义 task-level 二元聚合规则再使用合适的配对方法。直接给出主要速度终点的失败约定，例如在固定预算 τ 内完成任务的完成率与 time-to-success；未成功样本记入预设失败惩罚/预算上限或明确定义的竞争风险分析。将实际消耗时间、成功完成时间和任务完成率分别保留。不要把程序错误当作无信息删失，也不要将超时简单删除。

**原因：** 只有确定采样单位与失败处理，540 次潜在运行才对应一个可解释的统计研究，而非事后挑选成功样本。

## A3. 区分“后端支持可变 B”与“按对象选择 B 的策略确实有效”

**位置：** 大纲 §2；实验计划 G0/G1/G2（第 91 行）、E00、E08 和 E11。

文档已指出当前 auto 可能与默认 B 完全相同，这是非常重要的检查。但随后固定 B sweep 与按对象策略评价仍容易在总结时被混为一谈。固定 64 KiB/256 KiB/1 MiB/4 MiB 可以展示布局能力和敏感性；它不能单独证明当前按最终对象大小选择的策略优于一个合理固定布局。

**建议修改：** 在 E00 写明：若 G0 与 G1 的 effective-B 分布完全相同，G1 是配置等价/零处理差异对照，不能解释为独立的 B 优化。保留该结果，同时将 q 的条件效应单独归因。若后续研究提出新的逐对象 B 策略，必须作为新的设计与代码修订记录，冻结规则，并以独立任务/对象分布验证；不能在正式评价集上选择每个对象的最佳 B 再宣称在线策略效果。固定 B 的全信息最优值只能标作 oracle 参考。

**原因：** 标题中的 Variable-Granularity 可以描述提供的接口能力，但收益主张需要来自实际处理差异。当前文档已有足够基础，只需把这一判据写成明确的实验解释规则。

## A4. 具体限定 OverlayFS/reflink 与远端对象文件系统的比较边界

**位置：** 外部基线 B2/B3/B5，第 77–80 行；E03，第 172–176 行。

文档要求“统一 upper 持久化边界”，但尚未规定如何使本地 upper 与远端 EC 对象存储达到同等完成条件。仅在说明中写“统一”不能证明实现可比；把本地 fsync 和跨主机 remote-complete 直接排序会混入服务契约差异。

**建议修改：** 明确两张对照表或两个场景：本地已预置 lower、进程/主机本地持久化的工作区开销；具有远端共享与明确故障域持久性的服务场景。若给 OverlayFS 增加远端 stage/checkpoint，应单列该方案、计入其实际开销，并陈述 checkpoint 与每次 fsync 的语义区别。只在真正匹配的范围做因果速度结论，跨服务模型的结果作为工程参照。

**原因：** 这是强基线公平性最容易被质疑的地方，也可能比增加更多文件系统基线更影响论文可信度。

## A5. 为正式运行给出最小证据矩阵和成本上界

**位置：** §5.2 的 60-task panel；E13；大纲 §9 的六周左右执行建议。

60 tasks × 3 systems × 3 repetitions 已经等于单一固定实验场景下的 540 次完整闭环运行。若继续跨 cold/warm、多个并发点、重试/探索拓扑展开，规模会增长为数千次；此外还需新控制适配器、插桩和 17 个实验协议。文档正确声明不做全笛卡尔积，但还没有明确哪些闭环组合属于主结论必需、哪些只由机制信号触发。

**建议修改：** 增加一个执行层次表：必须先完成的 E00/语义与布局检查；主论文的最小机制对照；单一固定拓扑的正式闭环 panel；只有前三者成立后才扩展的并发/云/多语言敏感性。用 pilot 的 task duration 与 token 数估算 node-hours、storage-hours 和 model tokens，采用公式并保留待填值，不虚构价格或完成日期。为每阶段列出通过条件和取消/缩小后续矩阵的条件。

**原因：** 当前方案的覆盖面很好；优先级与预算决定它能否在真实资源下执行。OSDI 截止日期不应反过来迫使省略关键正确性工作。

## A6. 在摘要范例中同步体现尚未接通的联合路径

**位置：** 大纲 §1 的英文工作性摘要；§4 的实现边界第 7 项。

正文已经说明 Entity mount 与 Packed producer 的 hint 传参尚未完整接通。英文摘要范例却采用 `At object upload, BrewFS supplies a layout hint...` 的无条件现在时。读者只看范例时可能理解为三项设计已在论文主路径接通。

**建议修改：** 在该范例前后明确它描述 intended design，或在当前阶段写成 `The design supplies...` / `The prototype exposes...; the planned integrated path...` 等与实际状态相符的句子。在 E00 完成之前，不能以 abstract 的一般现在时掩盖组合接线缺口。最终作者稿可在真正接通后改回实现场景表述。

**原因：** 计划文本整体诚实，但摘要是最容易被摘录和独立阅读的部分，状态信息应当在摘录后仍然成立。

## 已满足、无需追加形式化检查的部分

- **问题与标题对应清楚。** 三项设计各有状态范围、机制、代价和实验，不将 Delta 误写为字节差分，也不把整个快照等同于单一 metadata packet。
- **近邻比较覆盖了真正冲突的路线。** 文档要求面对 OverlayFS、近期 agent 文件系统、DeltaFS、immutable/lazy image 以及较新布局工作，且不以只战胜 full copy 作为充分证据。
- **缓存与读取策略的混杂已经被识别。** 包括 effective B/q、whole-object fetching、SingleFlight、write budget 和 shared-bytes reply，优于把所有变化打包为“without optimization”。
- **正确性没有被性能测试替代。** E14/E15 包含操作契约、隔离、发布、缺失对象、校验和修复，且明确不把 fail-closed 等同于自动恢复。
- **负面结果已被纳入。** 高修改比例、随机访问、构建摊销、大顺序读、GC/repair 干扰均有计划。
- **格式与政策准确。** 12 页初始正文、参考文献另计、独立补充材料、双盲、公开系统匿名名称、当前 AI 政策及北京时间换算均与已核验的 OSDI 2027 官方页面一致。
- **不混淆交付与投稿。** internal draft、anonymous preview、未执行实验和作者责任的说明适当。

## 对初稿可接受状态的判断

这套材料可以作为内部研究初稿与实验筹划包交付，不应称为“已验证的 OSDI 论文”或“可直接投稿”。对于本轮交付，应完成 A1–A3 的解释性澄清，并将 A4–A6 明确到计划/摘要状态；正式实验前再填入真实硬件、版本、运行器与样本预算。实际执行若发现第三项缺乏独立效果，应调整论文论点与标题，而不应删去相反证据。

本次是对 supplied planning artifacts 的审阅，没有运行文件系统、复现历史结果或重新完成全部文献/源码核验，也没有证明实施计划一定能达到顶会录用标准。
